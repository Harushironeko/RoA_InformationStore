# ワールド側の実験「文章だけ通す」

ワールドを作る側（Unity / UdonSharp）への依頼書。公式サイトの内容を String Loading で読み、World Space の Canvas に出せるかを Unity エディタ上で確かめる。
データの形式は同じフォルダの `FORMAT.md` にある。この実験は形式を固める前の確認なので、**読みにくい点・足りない項目があれば形式の方を直す**。遠慮なく報告してほしい。

## 決まっていること

- 表示は World Space の Canvas（uGUI + TextMeshPro）。空間に物を置く展示はこの段階では考えない
- 動作は基本すべてローカル。同期はしない
- 更新ボタンは押した本人だけを更新する。後で「スタッフ認証された人が押すと、インスタンスの全員が更新する」を足す予定なので、更新の入口は引数なしの public メソッド1つ（例 `Refresh()`）にまとめておき、ネットワークイベントから呼べる形にする
- 同様に、後でスタッフだけが「いま開いている記事を全員に見せる」操作を足す予定。開く記事は「種類の名前」と「記事の `id`」の2つの文字列で指せるようにしておく（配列の何番目か、では指さない。並び順は更新で変わる）
- キャラクターの演者名は出す。物語と根源災害の Log は全文を出す
- 根源災害の演出（`scene` 行）と画像（`img` 行）と音声（`audio` 行）は、この実験では読み飛ばす

## 確かめること

### 1. 読み込み
- `VRCStringDownloader.LoadUrl` で `index.json` を読み、`VRCJson.TryDeserializeFromJson` で解析する
- `parts` のうち空文字でない枠だけ、`part-N.json` を読む。String Loading は**シーン全体で5秒に1本**で、同時に頼むと順不同になる。必ず1本ずつ、前の結果（成功か失敗）が返ってから次を頼む
- 読んだ `part` の `rev` が目次の `parts[N]` と違ったら、表示を変えずに60秒後にその枠だけ取り直す（3回まで）
- 使っていない枠の URL は 404 になる。空文字の枠は頼まないこと
- エディタの再生（ClientSim）で String Loading が動かない場合は、手元の写しを TextAsset で読ませて以降を進め、その旨を報告する

### 2. 解析の重さ
- `part-0.json`（約185KB）の `TryDeserializeFromJson` にかかる時間
- その後、全記事の全行を1回なめる時間（`VRCJson` は入れ子を使うときに初めて解析するので、ここで初めて重さが出る）。なめ方は「種類 → 記事 → `pages` → `body` → 行の各要素」
- 記事1件を開くときにかかる時間（長いのは根源災害の `alc-307`「不死蛾」と `alcase-12`「妄信」、社会の `alchenium-tech`、物語の4件）
- それぞれ、1フレームで終わらせた場合の止まり方と、数フレームに分けた場合

計測は `System.Diagnostics.Stopwatch` か `Time.realtimeSinceStartup` で。エディタの値で構わない（Quest の実機は後で測る）。

### 3. 表示
- 一覧：種類を選ぶと、記事の `title`・`sub`・`summary` が並ぶ。12種類すべて（公式サイトの10種類に Q&A と二次創作ガイドラインを足したもの。`news` と `staff` はいま0件なので「まだありません」と出す）
- 詳細：`info` を見出しと値の表で、`pages[].body` を上から順に部品を置いて出す。行の種類は `FORMAT.md` の表のとおり。部品（見出し・段落・台詞・項目・区切り線）は作り置きを使い回す
- 根源災害はページ（`Top` と Log）を切り替えられる。`link` 行を押すと、その記事（種類と `id`）を開く
- 年表は記事ではなく `[年, 月, 日, 種類, 名前, タグ, 本文, 記事の種類, 記事の ID]` の配列。年・月・日は数値（`VRCJson` では double になる）
- 知らない種類の行は読み飛ばす
- 1つの文字列は最大 2,000字。TextMeshPro の1部品に入れて崩れないか（頂点数の上限、ScrollRect の中での表示範囲）

### 4. 文字
- ワールドで使う日本語フォントのアセットに、`chars.txt` の全文字が入っているかをエディタ拡張で確かめる（`TMP_FontAsset.HasCharacters` など）
- 無い字の一覧を報告する。フォントに入っている文字の一覧（1ファイルに並べたもの）ももらえれば、`world/charset.txt` に置いて、書き出しのたびに「ワールドで出せない字」を公式サイト編集の画面に出せる

### 5. 更新
- 更新の入口（`Refresh()`）を呼ぶと `index.json` だけを読み、`rev` が同じなら「最新です（`generatedAt` の版）」と出して終わる
- `rev` が違えば、`parts` を比べて変わった枠だけ読み直し、揃ってから表示を差し替える。詳細を読んでいる途中なら、一覧に戻ったときに差し替える
- 押した結果は必ず出す：確認中 / 最新です / ○件更新しました / 読み込めませんでした
- 連打への備えとして、30秒は押し直せないようにする
- 入室時はビルドに同梱したスナップショット（`index.json` と使用中の `part`）をすぐ表示し、裏で目次を確認する

## 報告してほしいこと

1. String Loading はエディタの再生で動いたか（動かなければどう代用したか）
2. 解析・全行なめ・記事1件を開く、それぞれの時間と、止まりを感じたか。枠を分ける基準はいま 300KB で、これを変えるべきか
3. フォントに無かった字の一覧と、フォントに入っている文字の一覧
4. 形式で扱いにくかった点。たとえば「行を配列ではなく辞書にしてほしい」「`info` を `body` の行にまとめてほしい」「一覧用の項目だけを別の枠に分けてほしい」「年表の数値を文字列にしてほしい」など
5. 足りなかった項目、要らなかった項目
6. TextMeshPro で 2,000字の段落が問題なく出たか。上限を下げるべきなら何字か
7. 使った VRChat SDK と UdonSharp のバージョン
